================================================================================
                    VNPAY SANDBOX CLINIC FEE VERIFICATION GUIDE
================================================================================

1. OVERVIEW
-----------
This document outlines the operational verification procedure for the VNPAY
Sandbox integration for clinic consultation fees (CLINIC_FEE).
Constraint: This integration applies ONLY to CLINIC_FEE invoices. MEDICINE_FEE
is completely unmanaged by this payment flow.


2. ENVIRONMENT PREPARATION
--------------------------
In `backend/.env`, configure your VNPAY Sandbox credentials:

  PORT=3000
  DATABASE_URL="mysql://root:password@localhost:3306/booking_care_db"
  JWT_SECRET="your_jwt_secret"
  JWT_EXPIRES_IN="1d"
  JWT_REFRESH_SECRET="your_jwt_refresh_secret"
  JWT_REFRESH_EXPIRES_IN="7d"

  # VNPAY Sandbox Configuration
  VNPAY_TMN_CODE=DEMOV210
  VNPAY_HASH_SECRET=<your-sandbox-hash-secret>
  VNPAY_PAYMENT_URL=https://sandbox.vnpayment.vn/paymentv2/vpcpay.html
  VNPAY_RETURN_URL=https://<your-public-backend-domain>/api/payments/vnpay/return
  VNPAY_IPN_URL=https://<your-public-backend-domain>/api/payments/vnpay/ipn
  FRONTEND_URL=http://localhost:5173

Notice: For local development with live VNPAY callbacks, use a tunnel like ngrok:
  ngrok http 3000
and set VNPAY_RETURN_URL and VNPAY_IPN_URL to your ngrok forwarding URL.


3. DATABASE MIGRATION & PRISMA GENERATION
-----------------------------------------
Execute from `backend/`:
  npm run db:migrate
  npm run db:generate

The migration script `ensure-payment-schema.js` idempotently verifies and creates:
  - `invoices.payment_expires_at` (DATETIME NULL)
  - `invoices.vnp_txn_ref` (VARCHAR(100) NULL, UNIQUE)
  - Index `idx_invoices_payment_expiry` on `(payment_status, payment_expires_at)`


4. AUTOMATED TEST SUITE VERIFICATION
------------------------------------
Run backend tests:
  cd backend
  npm test

Expected: 41/41 unit & integration tests pass across:
  - VNPAY config validator (`vnpay.config.test.js`)
  - Pure HMAC-SHA512 signing & URL utilities (`vnpay.util.test.js`)
  - Atomic booking invoice transaction & format (`appointment-payment.test.js`)
  - Payment repository, IPN handler & background expiry sweep (`payment-expiration.test.js`)
  - Payment controller, security routes & callbacks (`payment-api.test.js`)

Run frontend tests & build:
  cd ../frontend
  npm test
  npm run build

Expected: 6/6 tests pass and Vite production bundle compiles cleanly.


5. END-TO-END SANDBOX SMOKE TEST CHECKLIST
------------------------------------------
Step A: Patient Books Appointment & Gets Redirected
  1. Log in to the frontend as a Patient user.
  2. Select a doctor schedule and confirm booking.
  3. Verify the browser is immediately redirected to VNPAY Sandbox payment page.
  4. Notice the payment amount on VNPAY matches the consultation fee (VND amount x 100 in cents).

Step B: Completing Payment via VNPAY-QR or Sandbox Bank
  1. Complete a test payment on VNPAY Sandbox (e.g. choose VNPAY-QR or NCB test card).
  2. Confirm VNPAY redirects back to `GET /api/payments/vnpay/return`.
  3. Confirm the backend redirects the browser to `FRONTEND_URL/payment/result?invoiceId=<id>`.
  4. VNPAY server triggers `GET /api/payments/vnpay/ipn`.
  5. The backend validates HMAC-SHA512, verifies amount, and marks invoice `payment_status = 'PAID'`.
  6. The `PaymentResult` page polls the backend status and renders "Thanh toán thành công".
  7. Navigate to appointment details and verify "Trạng thái thanh toán: Đã thanh toán" (green badge).

Step C: 10-Minute Expiration & Slot Release
  1. Book a new appointment but do NOT pay.
  2. In appointment details, observe:
     - Badge: "Chưa thanh toán" (amber)
     - Live countdown: "Thời gian thanh toán còn lại: mm:ss"
     - "Thanh toán lại" button is present and active.
  3. Wait until the 10-minute window expires (or simulate time advancement).
  4. Notice:
     - The background job (`payment-expiration.job.js`) sweeps every 60s.
     - The invoice remains `UNPAID`.
     - The appointment status transitions to `CANCELLED`.
     - The schedule's `booked_patients` is decremented by 1 (releasing the slot).
     - In appointment details, the countdown disappears and badge displays "Hết hạn thanh toán".
     - The "Thanh toán lại" button is automatically hidden.

Step D: Scope Isolation Guard
  1. Confirm that medicine fees (MEDICINE_FEE) and prescription workflows are unchanged.
  2. No medicine invoices are ever handled or altered by VNPAY endpoints or expiration sweeps.
